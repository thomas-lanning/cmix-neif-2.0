# Quantization research loop

Read [the prize rules](../prize-rules.md) and the [operating instructions](../README.md). The objective is to minimize full packaged bytes subject to exact decoding and both resource limits. During screening use the six discovery windows and the doubled packed-weight cost. The other six are a confirmation set. Once used for choosing ideas, they are no longer an independent check.

1. Start from the pinned upstream weight file. Write one hypothesis and its predicted direction in your experiment branch. Edit `candidate.py` or an experimental training/export recipe. Preserve the published NP2 geometry for this replay.
2. Run the bounded sweep on the prepared native worker. Record the source hash, exported container hash, exact size, per-window effects and both proxy totals. The controller keeps the successfully exported model when both halves improve against upstream. Read previous trials before proposing another.
3. Compare promising exports against the current best on the same suite. Retain each model's hash and logs. Investigate disagreements across windows before combining hypotheses. Budget at most three exports per sweep. A process failure is a failed experiment.
4. For promotion, freeze the candidate, run a disjoint full-stream suite and then embed it in both halves of a release build. Restamp both weight checks against the actual bytes. Compression and decoding must agree on a clean x86 host. Score both executables and required arguments. Only a complete run and the resource checks establish a prize result.

The evaluator, fixture generator, scoring formula, baseline weights and accounting stay fixed during a sweep. GPU training and changing model dimensions are separate campaigns. A new geometry requires matching native kernels and a new calibration.

## Broader experiments

Use a fresh result directory for each campaign. The original layout is the control. The native kernels also support shrinking the MLP widths in blocks 0 through 11 in multiples of 16. Keep the final four MLPs at their original widths for the online fast-weight head.

- `campaign.py search` varies the weight alphabet and rounds BF16 row scales. It selects promising layer groups, refines the fraction and alphabet, then tests combinations.
- `activations.py collect` records the integer inputs that the released up and down projections actually receive. `calibrated.py gram` computes input covariance on discovery documents. `calibrated.py search` uses it to select neurons, compensate the remaining projections and fit smaller alphabets.
- `rate_distortion.py` changes individual integer weights. In each coordinate update it prices an integer symbol by its observed frequency and estimates prediction damage from the native activations. Exporting each candidate gives its actual NP2 size.
- `distill.py` fits pruned quantized blocks to their original outputs on separate training articles. The initial floating-point calculation must reproduce the original block’s quantized activations exactly on its validation sample. The native whole-model replay determines whether a fitted block is worth keeping.
- `campaign.py validate` replays frozen, hash-checked candidates on a new suite. Use the early 48-article suite to screen again, and reserve later articles from the full coder stream for a separate check.
- `symmetry.py` flips integer row signs and BF16 scale signs together and verifies both the effective tensor values and the exact neuron order. `sign_search.py` uses the NP2 coder's causal width buckets to propose further flips. It accepts a tensor change only when the actual NP2 bytes decrease.
- `head_fit.py` checks a differentiable replica of the final unembedding and PPMd logit mixture against the native head before training. `tail_profile.py` and `tail_qat.py` extend the same objective through the final attention-residual mixture to the quantized last MLP. Fit on separate documents, then evaluate the exported model on the native scorer.
- `vector_search.py` prices an entire rANS codebook container, including the remaining NP2 weights, escaped vectors and table metadata. Each retained vector package must unpack into the exact tensors used for its native replay. A prize trial also needs a counted native reader.
- `cache_keys.py` stages a source experiment on the cache of earlier transformer states. It tests alternative four-bit approximations to each stored vector. For each experiment, compare the native mixed-coder output on the same stream checkpoints, relative to a reference confirmed against the published archive.
- The manual **Benchmark semantic-cache quantization on matched native queries** workflow decodes the published arithmetic payload with its original key and index. After checking the decoded bytes against independent input hashes, it tests alternative 64-byte keys on identical stored vectors, queries and candidate lists. It also fits an 8- or 32-byte table of integer weights for a weighted cosine, using the probability of the observed byte as the training objective. It freezes the choice on the first usable span, then scores later spans. Choose `early` for three intervals ending at 18 million canonical bytes and `full` for a wider test ending at 40 million. The measured target probability is a proxy for the full mixer. A change to candidate retrieval or indexing requires its own native experiment.
- `layer_search.py` screens the attention, MLP up and MLP down projections of each layer separately, then refines their integer alphabets on two disjoint 24-article training folds. It prices each candidate using the measured package and the calibrated transfer from neural predictions to archive bytes. The search freezes up to four combinations before validation.
- Use `fixtures.py --windows 96 --midpoints --exclude-manifest FILE` to prepare a later article set disjoint from the first late validation suite. Freeze candidate hashes before opening their results. `paired_stats.py` reports a stratified article bootstrap for the projected change, keeping the measured packed-weight cost fixed.

The prefix harness in `instrument_prefix.py` records the actual bytes emitted by the original mixed predictor at fixed stream positions. Verify the reference payload against the published archive. Use a weak and a stronger candidate from different search families on exactly the same interval. `transfer.py fit` reports each measured payload difference, estimated head difference, and both halves of the estimate. Small denominators or opposite signs between the halves make the transfer uncertain. `shortlist.py freeze` records the two controls, source model hashes and a selection across several transfer assumptions. `shortlist.py replay` evaluates that frozen list on fresh documents.

For a release trial, run `stage_release.py CANDIDATE SHA256 FRESH_TREE`, build that tree offline with upstream’s `build.sh`, and run `research/baseline.sh --candidate COMP_SHA256 COMP9 ENWIK9 FRESH_RUN_DIR` on one core. This stages both embedded weight copies from the same checked model. Archive bytes, decoded data and packaged executable sizes determine the outcome.

## Running repeated experiments

This setup follows Karpathy's editable experiment program and fixed evaluator. A command-based controller can read the printed `METRIC` lines. The same campaign can also run from a coding agent with these instructions. [Karpathy's autoresearch](https://github.com/karpathy/autoresearch) · [pi-autoresearch](https://github.com/davebcn87/pi-autoresearch) · [Claude Autoresearch](https://github.com/uditgoenka/autoresearch)

Start the agent in a dedicated experiment branch with this file as its instruction. Give it the replay binary, fixture directory, persistent results directory and a budget of trials or wall time. Reproduce the identity result and run a zero-fraction export once with `loop.py --fractions 0` to measure the cost of reserializing the published tensors. Record the starting commit and both controls in the campaign log.

After each sweep, inspect `trials.jsonl` and `sweep.jsonl`. Choose one new hypothesis from the results, write the rationale before running it, edit the exporter in the experiment branch, commit it, and rerun the same evaluator. Record the commit, result and keep/discard decision. Compare a change with the best retained model as well as the published reference. Keep the generator snapshot and evidence for discarded trials. Continue to the supplied budget or until an environmental failure prevents measurement. If a change works only on the discovery windows, keep the incumbent. The three row fractions in the first sweep seed this process.

For hosted trials, first run the manual **Build and run the portable quantization benchmark** workflow. It builds the native tools, hashes the complete original C40 prior stream while retaining just the rows needed for the benchmark, and reproduces both the identity and a changed-weight control. Its `portable-c40` artifact contains the twelve window files and a Linux replay executable.

Dispatch **Run a quantization experiment on the fixed quick benchmark** from the fork's main branch for each hypothesis. Supply the experiment branch or commit, the hypothesis and the exporter arguments. The workflow checks out a separate pinned evaluator, verifies the fixture manifest, rebuilds the native scorer, and records both commits, the fixture build, weights and a keep/discard decision. The equivalent local option is `loop.py --generator /path/to/experiment/candidate.py` with the same replay, suite and results arguments.

The **Fit and validate a quantized correction to native byte probabilities** workflow uses a completed C40 build. It records the original transformer's probability of each possible next byte and groups the predictions by confidence and agreement with PPMd. Four discovery articles fit each table, two more choose its size and regularization, and the remaining six measure the frozen procedure. The lookup table occupies 8 or 24 bytes before executable packaging. An external test can reuse the table with `head_calibration.py --frozen` and a new disjoint C40 suite.

Build the portable benchmark with `include_validation=true` to get `validation-c40`. Pass that build number as `validation_run` in the quick sweep to automatically replay every model that improved on both six-article splits. The follow-up checks the independently generated 48-article manifest and records the frozen hashes before reading the validation scores. For previously completed runs, dispatch **Validate frozen quantization exports on 48 independent articles** with the original run number and artifact name.

## Starting a quantization-aware training run from the published model

Run `python3 research/quant/qat_seed.py /scratch/release-plain.c5` in a NumPy environment. This converts the published NP2 weights into the plain v5 file read by the training tools. It checks each tensor's name, type, shape and byte values with the trainer's own v5 reader before publishing the file. The reference conversion produced 597 identical tensors and 3,765,762 bytes with SHA-256 `26e572080c240b6c8eb59a8dc8aab6ab6591efac695424f5942abf1d8fdde712`.

With the [upstream training environment](../../training/README.md) assembled, its CPU conversion step can then produce the trainable checkpoint and the per-row integer ranges.

```sh
export TFT_TREE=/scratch/trainer PKG=/scratch/training-package
source training/tf/3_train/tree/exp.env
python3 training/tf/3_train/container_to_tch.py --container /scratch/release-plain.c5 \
  --cfg training/tf/3_train/chain/06_qat.json --strict /scratch/strict.tch \
  --qrow /scratch/row-ranges.npz --report /scratch/conversion.json
```

The upstream training chain used a rate coefficient of `2.7e-9` mean nats per model bit. With two stored copies, 487,298,491 scored targets, and a measured fraction α of a primary-head loss change transferred to the archive, the local break-even coefficient is `2 × ln(2) / (α × 487298491)`. The two prefix controls imply a range from `1.44e-9` to `3.80e-9`. This is a starting range for paired experiments. Rank exports using measured packaged weights, fresh articles and the native mixed-coder interval. [Prefix measurements](prefix-calibration.json)

An independent CPU run loaded the recovered weights into upstream's 9,325,119-parameter model. Its quantizers reconstructed all 155 integer weight matrices exactly. The `quantization-aware-start` artifact contains `strict.tch`, per-row ranges, the environment and digests. [Verified training checkpoint](https://github.com/thomas-lanning/cmix-neif-2.0/actions/runs/44240939697)

For full-corpus fitting, run the late-benchmark workflow with `dataset=training`. Its `full-corpus-training` artifact contains 1,024 training articles distributed from 45 million canonical bytes onward. The generator first selects the 12-article and 96-article evaluation sets and excludes both from training. The build checks the complete 203 GB trimmed prior stream against the published digest. Pass the completed run ID as `corpus_training_run` to the QAT workflow. Supply `fixture_run` for the early quick benchmark and `training_run` for its independent 48-article validation artifact. The trainer checks both frozen manifests and checks the 1,024-article package receipt before fitting.

A successful full-corpus training build on the fork's main branch starts a bounded CPU experiment automatically. It calculates token-loss gradients, measures three edit budgets on the quick benchmark and uses discovery scores to try up to two neighbouring budgets. Exports that improve both quick splits go to the fixed 48-article check. The best candidate with a negative independent estimate proceeds to the real 20-million-byte arithmetic-payload test. [Training workflow](../../.github/workflows/corpus-training.yml)

The same frozen weights advance to 40 million preprocessed bytes if they reduce the measured 20M payload or the matched interval's projected total entry size. The paired test checks the control against the published archive and the candidate against its prior 20M bitstream. A fresh runner decodes the candidate and checks all 40M bytes against the independent canonical hash. The report records the overall difference, the difference on the added 20M and the cost of both weight copies. The 1,024-article training region starts after 45M. The 40M prefix overlaps the early screening articles. A manual dispatch runs the frozen fitted mixer against upstream with the same checks. [40M workflow](../../.github/workflows/large-prefix.yml)
